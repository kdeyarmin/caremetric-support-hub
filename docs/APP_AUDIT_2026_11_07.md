# Application audit — November 7, 2026

Reviewed from `ad08ba8` on `main`. This change fixes reproduced frontend defects and adds regression coverage. It does **not** certify that every production integration works: the hosted database is missing recent fixes, and authenticated external-provider workflows still need release verification.

## Fixed in this change

| Finding | Result | Verification |
| --- | --- | --- |
| A late session check could restore the signed-in UI after sign-out; an older actor lookup could begin another private-data load. | Session and data requests are invalidated together; stale session/actor results are ignored. | Two ordering regressions, including a deferred actor lookup. |
| Overview case links all opened the first case, and the customer “New support case” link did not open the form when cases existed. | Links carry the selected case ID or `new=1`. | Navigation tests and browser flow. |
| The queue kept its initial case snapshot even after the shell refreshed it. | Navigation snapshots update the visible rows and selection, but cannot overwrite a newer local reload after a save. | Navigation regressions with changed server data and a delayed pre-save snapshot. |
| An empty public catalog caused repeated loads. | Successful public loading is tracked explicitly instead of inferred from a nonempty product array. | Empty-catalog regression. |
| HTML/empty gateway failures exposed JSON-parser errors; an empty 401 failed to notify the shell of session expiry. | HTTP failures have readable messages and a status, and expiry is signaled before parsing. Cancellation remains cancellation. | HTML, empty-401 and JSON-null regressions. |
| Chat polling errors hid an existing conversation; delayed polls could overwrite a newly sent reply. | Existing messages remain visible on errors, retry is available, only 404 means no chat, overlapping polls are prevented, and old polls cannot replace mutation results. | Four chat regressions plus the existing chat/inbox tests. |
| Failed sign-out and denied clipboard access rejected without useful UI feedback. | Both actions explain the failure and permit retry/manual copying. | Sign-out regression and a denied-clipboard browser check. |
| Knowledge filters and the article close button lacked accessible names; secondary text/statuses failed contrast checks. | Controls are named and affected text colors are darker without changing layouts. | Automated accessibility scan of 26 desktop routes, plus the case workflow. |
| Local setup instructions required Node 22 despite the package requiring Node 24. | README now agrees with `package.json`. | Configuration comparison. |

No uncaught page errors. Mobile and desktop screenshots were inspected.
