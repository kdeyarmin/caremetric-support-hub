# First-use customer registration

> **Turned off.** The Hub is private to its owner (see [owner-only access](APP_SMS_SIGNIN.md#owner-only-access)), so customers no longer get Hub sign-ins. This page describes the retired flow.

An administrator with a current app SMS session reviews a native user/account relationship, a mobile number and the customer account name in **App integration → Invite a new Hub customer**. CareBase, Breathe, EMR, Go, PennSync and Intel each use their fixed native endpoint and current mapped administrator authority. The proof contains identifiers, relationship facts and a state digest; it never treats a native email or phone as proof of SMS ownership.

Preview lasts 60 seconds. Issuing the reviewed invitation repeats the native check, binds the current administrator session and retains one request ID and 256-bit code after an uncertain response. The server stores only the code hash. The 15-minute code is shown in the current administrator view for the administrator to give to the intended person. No invitation or text is sent automatically. Pending invitations can be explicitly revoked; a lost code must be revoked and replaced.

The person opens `/join`, enters the code and reviewed phone number, and consents to a verification text. CareMetric's existing SMS provider verifies the code in the app. HttpOnly Secure SameSite cookies bind the challenge and session. Persisted resend, phone, client, total and verification-attempt limits are shared with normal sign-in. Used, expired or revoked invitations and revoked issuing administrator sessions fail closed. Codes, phones, provider responses and credentials are not logged or put into URLs.

Successful SMS verification creates a minimal durable identity, profile and app session. It creates no product membership, staff permission, tenant or case intake. After claim, the administrator selects **Review app access**, obtains fresh native proof and reviews the separate customer pairing. CareBase customer pairing reuses its canonical native issuer, principal and organization mapping, including administrators without employee records. It creates no employee binding or learning receipt. Subsequent course/learner setup uses the same canonical Hub identity and separately verified native employee relationship. Existing Hub identities and established native mappings cannot be replaced through this flow.

Deploy the reviewed registration migration and guarded feature declaration before the frontend. The declaration preserves existing features and checks that registration functions are unavailable to anonymous and browser-authenticated database roles. No real customer invitation, SMS send, native mapping or grant is created by deployment. The isolated PostgreSQL/HTTP CI fixture exercises all six products, cookies, consent, quotas, stale proof, replay, administrator revocation and the absence of grants at claim; UI tests cover review and correction flows.
